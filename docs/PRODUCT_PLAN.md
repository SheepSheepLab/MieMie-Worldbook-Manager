## 2. 产品定位

咩咩世界书管理不是重新创造一套世界书格式。

它是：
SillyTavern 原生 World Info / Lorebook 的高级管理前端 + AI 长期资料维护工作区。

核心目标分为三件事：

### 世界书人工管理

编辑、复制、删除、拖拽排序、修改 SillyTavern 世界书的全部原生条目设置。

### AI 辅助长期资料维护

多选世界书条目 + 指定 AIRP 剧情楼层 → AI 根据当前已经发生的剧情更新资料 → 人工确认 → 写回原条目。

### 长期记忆整理

对记忆条目进行优化，或执行“大总结”，把当前世界资料整理成日常记忆 / 重大记忆，并安全写入世界书。

正式实现前，先读取当前 SillyTavern release + 当前 Tavern Helper API。

不要靠印象复刻世界书 UI。

确认：

- Worldbook 文件结构；
- Entry UID；
- 当前所有 World Info Entry 字段；
- 读取世界书方法；
- 创建条目方法；
- 更新条目方法；
- 删除条目方法；
- Order 的实际存储逻辑；
- enabled / disabled；
- Strategy；
- Primary Keys；
- Optional Filter；
- Selective Logic；
- Position；
- Depth / Role；
- Probability；
- Inclusion Group；
- Group Weight；
- Prioritize Inclusion；
- Group Scoring；
- Automation ID；
- Character Filter；
- Triggers；
- Scan Depth override；
- Recursive options；
- Sticky / Cooldown / Delay；
- Vectorized；
- Outlet；
- 当前版本新增的其他字段。

SillyTavern 现在的 World Info 已经包含大量高级能力，不应该自己定义一个简化结构再反向重建世界书。GitHub

原则：

读取原对象 → 局部修改指定字段 → 原样保留其他字段。

不得因为咩咩管理器暂时没识别某个字段，就在保存时删除它。

## 6. 右侧 · 世界书管理区域

### 6.1 条目排列

世界书条目始终按照 SillyTavern 的实际 Insertion Order 从大到小排列。

例如内部：

```text
1 2 3 4 5
```

管理器显示：

```text
5
4
3
2
1
```

但：

用户界面不显示 Order 数字，也不提供手填 Order 的输入框。

排序全部通过拖拽完成。

ST 官方定义本身也是更高 Order 更接近上下文末端；因此咩咩 UI 顶部对应更高 Order。GitHub

## 7. 新建条目

新条目默认加入列表顶部。

如果现有最大 Order 为：
5
新条目逻辑上成为：
6
显示：

```text
6
5
4
3
2
1
```

但 UI 不显示这些数字。

非常重要

不要每次拖动都简单把整个世界书重新编号成：
1...N
因为不同世界书可能通过 Order 共同参与排序。

优先采用：
最小修改 Order 的方式。

例如交换 / 重新分配必要条目的已有 Order 值。

只有不存在安全排序方案时才做整体重排。

## 14. 「同步最新资料」

这是本项目最核心功能之一。

作用：
根据已经发生的 AIRP 剧情，更新用户主动选择的世界书资料。

例如选中：

- A角色资料
- B角色资料
- 某组织
- 某地点

然后点击：
同步最新资料

## 15. 同步 · 楼层范围

弹出同步窗口：
剧情起始楼层：[____]
剧情结束楼层：500
结束楼层自动读取当前最新楼层，不能超过当前聊天。

例如玩家填写：
200
则本次 AI 输入：
200 ～ 500 楼剧情

同时发送：
用户所选择的世界书条目当前资料。

所以同步请求逻辑为：

```text
Selected Entries + AIRP Floors[start → latest] → AI
```

由 AI 判断这些资料是否需要根据当前故事更新。

## 16. 同步结果不得直接覆盖

AI 返回后：
绝对禁止立即写世界书。

进入：
同步校对界面
每个 Entry 显示：
原内容
与：
AI建议内容
并标注：

- 无变化
- 建议更新
- 存在冲突

用户可以逐条决定：
应用 / 不应用
最终：
确认同步
以后才真正写回。

只修改：
AI明确需要修改的 Entry Content。

标题、Keys、Position、Strategy 等其他字段全部保持原样。

## 17. 同步输出结构

提示词以后再调。

但是第一版就必须先定义稳定的结构化输出协议。

建议类似：

```json
{
  "updates": [
    {
      "uid": 123,
      "status": "update",
      "content": "新的完整内容"
    }
  ]
}
```

状态：

```text
unchanged
update
conflict
```

AI 不允许直接操作世界书。

AI 只是返回：
修改建议。

写入权永远属于管理器 + 用户确认。

Tavern Helper 当前支持 json_schema 强制结构化生成，可以直接用于这里。GitHub

## 18. 「优化」

优化主要用于已经积累非常大的：
记忆类 Entry。

例如某个 Entry 已经达到：
10k+ token
玩家勾选后：
优化
输入：
被选 Entry 的当前内容。

AI负责：

- 去重复；
- 合并；
- 压缩；
- 保留关键事实；
- 清理冗余。

具体 Prompt 后期再写。

底部：

恢复成 AI 刚返回的优化结果。

点击：
确认替换

## 20. 左侧 · AI 长上下文工作对话

左边不是普通“问一次答一次”。

它应该像一个真正的小型聊天窗口。

支持：

- 用户消息；
- AI消息；
- 长对话历史；
- 连续追问；
- 滚动历史；
- 自动滚到底部；
- 多轮上下文。

主要用途：
用户直接和 AI 讨论世界书有没有问题、人物设定是否冲突、某条资料应该怎么写等。

## 21. AI 对话使用默认全局 API

咩咩世界书管理：
不支持自己的 API 地址。

不提供：

- API URL
- Key
- Model
- Proxy Preset

配置页。

全部直接使用：
当前 SillyTavern 已配置的全局 API / 当前模型。

Tavern Helper 的生成接口在不提供 custom_api 时即可使用当前 ST source；因此没有必要再保存一次用户 API Key。GitHub

这也是硬性设计原则。

## 22. AI 工作对话自己的历史

这个对话框拥有自己的消息历史。

不要把这里的问答写入：
AIRP 正式剧情聊天。

建议按：
当前聊天 + 当前世界书
保存工作对话。

例如：
同一角色、同一聊天、同一本世界书

重新打开管理器以后仍能继续之前的工作讨论。

切换世界书则切换对应工作记录。

## 23. AI 工作对话的世界书参考

AI对话应能够读取：
当前打开世界书的最新内容。

这样用户才能问：
“这几个人物资料有没有矛盾？”
“帮我看看设定是不是重复了？”

但每一轮生成前都重新获取世界书最新状态。

不要启动时读取一次然后永久使用旧副本。

具体世界书注入 Prompt 后期再调。

世界书管理区提供：

目标：

## 34. 日常记忆 / 重大记忆条目查找

确认以后，管理器首先查找：
日常记忆对应 Entry
重大记忆对应 Entry
匹配规则由后续用户提供的正式 AIRP 世界书格式 / Prompt 决定。

第一阶段先留 Matcher 接口，例如：

```text
DAILY_MEMORY_MATCHER
MAJOR_MEMORY_MATCHER
```

不要靠模糊 AI 猜测。

## 35. 没有对应 Entry

如果不存在：
自动创建。

## 36. 存在多个对应 Entry

如果检测到：
两个或更多“日常记忆”

或者：
两个或更多“重大记忆”

不能擅自选。

弹窗：
检测到多个目标条目，请选择本次写入位置。

玩家手动选择。

## 37. 写入方式：追加，而不是覆盖

这是硬性要求。

如果已有：
日常记忆
其原始 Content：
AAA
本次总结：
BBB
结果：

```text
AAA
BBB
```

也就是：
在原内容底部续写。

不是：
BBB
把 AAA 替换掉。

重大记忆同理。

## 38. 清理变量 Entry

大总结确认后，还必须检查：
是否存在「清理变量」对应 Entry。

具体 Matcher 同样后期根据实际 AIRP 世界书确定：

```text
VARIABLE_CLEANUP_MATCHER
```

如果存在：
保留。

如果不存在：
自动创建。

并放在：
世界书最顶部 / 当前最大 Order 的位置。

原则：

```text
newOrder = currentMaxOrder + 1
```

或采用 SillyTavern 当前等价的安全逻辑。

## 39. 总结后的楼层隐藏

大总结全部写入成功后：
隐藏最后一层之外的所有旧楼层。

这里同样属于 AIRP 专用世界书规则。

开发前必须通过真实 AIRP 世界书确定：

- 什么是“楼层 Entry”；
- 怎样判断楼层编号；
- 什么字段代表隐藏；
- “最后一层”如何确定。

不得开发者自己猜字段。

整个过程顺序应为：

```text
总结 → 人工校对 → 确认 → 写入记忆 → 确认清理变量 Entry → 隐藏旧楼层
```

任何一步失败：
停止后续修改并报告。

## 40. 大总结必须可回滚

因为它会同时操作很多 Entry。

执行前：
保存完整受影响 Entry Snapshot。

如果中途失败：
不得留下：
“日常记忆写成功，但是重大记忆没写，楼层已经隐藏了一半”

这种半完成状态。

第一版至少实现：
内存事务式回滚。

如果条件允许，再保存最近一次操作备份。

## 41. AI Prompt 暂缓

目前：
不要花大量时间打磨 Prompt。

只需要先留四套独立 Prompt Adapter：

```text
WORKSPACE_CHAT_PROMPT
SYNC_PROMPT
OPTIMIZE_PROMPT
SUMMARY_PROMPT
```

其中：
大总结 Prompt 用户已有自己的版本，后续由 SheepSheep 自行补入。

现在开发目标是：
确保数据进得去、结果回得来、审核流程正确、写回安全。

## 42. AI 请求必须互相隔离

每类生成拥有独立：
generation_id
例如：

```text
miemie-wb-chat
miemie-wb-sync
miemie-wb-optimize
miemie-wb-summary
```

并使用：

```text
should_silence: true
```

避免咩咩世界书里的后台生成把 SillyTavern 正常发送按钮变成停止按钮。

## 43. AI 操作不修改正式聊天

以下所有生成：

- 左侧对话
- 同步
- 优化
- 大总结

都属于：
后台工作请求。

不得向 AIRP 正式聊天新增 AI 消息。

AIRP 聊天只能被读取作为资料源。

## 44. 并发和冲突检测

这一点很重要。

因为未来：

- 蝴蝶效应引擎；
- 创意工坊；
- 其他脚本；

也可能操作世界书。

因此用户打开编辑窗口以后：
管理器记录：
Entry 原始版本。

真正保存前：

### 最终设计原则

这个项目的核心不是：
“把 SillyTavern 世界书界面重新画一遍。”

真正核心是：
把世界书从一个需要人工逐条维护的资料库，变成一个可持续维护整个长期 RP 世界状态的工作台。

人工管理解决：
“我想自己改。”

左侧 AI 工作区解决：
“我想和 AI 一起研究怎么改。”

同步解决：
“剧情已经推进几百楼，角色资料该跟着变化了。”

优化解决：
“记忆太大了，需要整理。”

大总结解决：
“一个阶段结束，需要把零散剧情正式沉淀成长时记忆。”

而所有 AI 工作最后都遵守：
AI提出建议，人决定是否落库。
